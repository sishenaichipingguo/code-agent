## 草稿

### 问题：我的 agent 有健忘症

我每天都用一个终端编程助手。它在「当下」的事情上很强——读文件、改代码、跑命令。
但每个新会话都从零开始。我得循环往复地重复同样的事实：

- 我们用 pnpm，不用 npm
- API 处理函数在 `src/api`，每个路由一个文件
- 我偏好具名导出
- PR 描述要简短，先写「为什么」

感觉就像每天早上都在重新培训一个新来的外包。模型不笨——它只是没有连续性。
所以我把记忆做进了 agent，并尽量用一种我自己真正信得过的方式来做。

### 设计目标：你能读懂的记忆

「agent 记忆」最省事的做法，是把所有东西都塞进一个向量数据库，然后指望语义检索
能捞出对的东西。我不想把那个当成**主要**存储，原因只有一个：我读不懂它。当 agent
干了奇怪的事，我想打开一个文件，清清楚楚看到它以为自己知道些什么。

所以核心存储是仓库里的纯 Markdown 文件：

```
.claude/memory/
├── MEMORY.md              # 人类可读的索引
├── user_indent-style.md   # 「2 空格缩进，偏好具名导出」
├── project_api-layout.md  # 「REST 处理函数在 src/api，每个路由一个文件」
└── feedback_pr-style.md   # 「PR 描述简短，先写为什么」
```

每条记忆是带一点 frontmatter 的 Markdown：

```markdown
---
name: indent-style
description: 代码格式偏好
type: user
created: 2026-01-12T09:30:00Z
updated: 2026-01-12T09:30:00Z
---

使用 2 空格缩进。相比默认导出，偏好具名导出。
```

分四类，因为记忆并非都一样：

| 类型 | 记录内容 |
|------|----------|
| `user` | 个人偏好 / 工作风格 |
| `project` | 这个代码库的约定与结构 |
| `feedback` | 你给 agent 的纠正 |
| `reference` | 值得留存的文档、链接、事实 |

因为就是仓库里的文件，记忆是可检查、可编辑、可 diff、可纳入版本控制的。给你
agent 的「大脑」做 code review。如果队友 clone 了仓库，他们也会拿到项目记忆。

### 让它毫不费力：自动提取

需要你手动管理的记忆，就是你不会用的记忆。所以对话结束后，一次 LLM 处理会审阅
记录，提取值得长期保留的事实——并跳过索引里已有的。提示词大致是：「返回一个值得
跨会话保存的记忆条目 JSON 数组；跳过已知的；没有新东西就返回 []」。

你也可以显式来：*「记住我们用 Docker Compose 部署」* 会立刻写一条。在意的时候显式，
不在意的时候自动。

### 当文件不够用时：本地语义检索

纯文件很适合回答「你了解我 / 这个项目什么」。但不擅长回答「我们以前遇到过类似这样
的错误吗」——尤其要跨几百次过往会话。这正是语义检索发挥价值的地方——作为**补充**，
而不是替代。

一个可选的后台 Worker：

1. 通过 hook 捕获观察记录（工具调用、文件操作）
2. 用 `all-MiniLM-L6-v2`（384 维，通过 transformers.js）在本地生成 embedding
3. 把向量存进 SQLite + ChromaDB
4. 提供一个相似度检索 API

关键词是**本地**。embedding 在你的机器上生成。没有 embedding 的 API、什么都不
往外发。唯一的网络调用是发给你选的模型服务商——而如果那是通过 Ollama 的本地模型，
那就什么都不出本机。

Worker 是 CLI 通过 HTTP 通信的一个独立进程，所以它完全可选、非侵入：有它没它
agent 都能工作。

### 我学到的

- **可检查胜过聪明。** 能 `cat` 一个记忆文件、手动改掉它，比任何排序算法都救过我
  更多次。
- **自动提取需要一个跳过清单。** 没有「跳过已知的」，你会很快被一堆近乎重复的记忆
  淹没。
- **本地 embedding 足够好。** all-MiniLM-L6-v2 很小，但对「提醒我我们关于 X 决定了
  什么」这类召回完全够用。
- **记忆是个 UX 问题，不只是存储问题。** 难的不是把事实放哪——而是判断什么值得留，
  并在对的时机把它呈现出来。

### 试一试

开源（MIT），TypeScript + Bun，一行命令安装：

```bash
curl -fsSL https://raw.githubusercontent.com/sishenaichipingguo/code-agent/main/install.sh | bash
```

仓库：https://github.com/sishenaichipingguo/code-agent

还很早期（v0.1）。基于文件的记忆和自动提取现在能用；语义 Worker 已接上但属实验性。
很想听听对记忆模型的反馈——纯文件是不是对的原语，以及你会希望随时间如何给记忆
划定范围和设置过期。
